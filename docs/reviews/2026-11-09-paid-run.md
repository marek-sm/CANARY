### #54: non-blocking, open

- **N-54-1.** A suite that calls `sys.exit` could end the script with no report. None of the committed suites does (November 8 fix review).
- **N-54-2.** The D1 and D2 suites run in one process, so they share module state. Running D1, then D2, then D1 again passed.
- **N-54-3.** The code binding compares test sources, not pytest's cached bytecode in `tests/__pycache__`. It doesn't check the provenance's recorded `dirty_paths` or environment digest either, which the paid-run gate already refuses.
- **N-54-4.** `068602a` is a merge commit that also changes code: it moves the suites in-process and adds the code check. A reader of `d3178d9` alone sees the subprocess version.
- **N-54-5.** The test helper's module-level `REQUESTS` dict couples `events()` to an earlier `result()` call.
- **N-54-6 (non-blocking, classified by the project lead on November 9; the fix review proposed blocking).** The code binding trusts git's view of the checkout. Deliberate tampering by whoever runs the script defeats it. Examples:
  - a forged pytest cache file in `tests/__pycache__`;
  - `git update-index --skip-worktree` or `--assume-unchanged`;
  - an untracked module under `tests/` that shadows a bound one;
  - `git replace`.

  Only the project lead runs readiness, on the project lead's machine, the same trust `paid_run` places in that checkout. So the binding catches accidental changes, not forgery, and the Gate 2 record states this.
- **N-54-7.** Code the suites import outside the bound directories isn't bound, such as `agent/loop.py` and the `runner/` imports in `tests/conftest.py`. The D1 record checks cover what that code produces.
- **N-54-8.** The provenance's recorded `dirty_paths` aren't read. A bound file edited mid-grid and reverted before readiness binds.
- **N-54-9.** `tests/conftest.py` and `pyproject.toml` are bound. Merging `main` into the readiness checkout after the grid can unbind them, so run readiness from the grid's checkout.
- **Q-54-1 (the project lead's ruling, November 9: keep the behaviour, and state it in the Gate 2 record).** Decision 0028 item 5 says the readiness script compares only the scoring digest. It names two changes that must not be refused: a runner fix made during a resumed grid, and report code that lands later. Both still bind. A resume across a change to `defenses/`, `oracles/`, `channels/`, `schemas/`, or `fixtures/` now leaves both defenses not ready, because no single checkout matches both commits. That grid would have measured two versions of a defense. The record doesn't cover this case, so the project lead ruled: the behaviour stays, and the Gate 2 record states it.

No blocking finding.

- **N-82-3 (non-blocking, design).** Each resume made before the cause is fixed uses up one retry on the open trial. Two outages already reach the 5% loss rule's limit of about 4 of 90 trials. Resume only after fixing the cause.
- **N-80-1 (non-blocking).** If bwrap dies before the tool sets its death signal, the tool's new parent never dies. This race is documented in `tools/no_exec.py`, and its odds are negligible.
